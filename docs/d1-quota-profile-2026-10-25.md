## Вывод: главный жгут — `/sync`

Каждый **холодный** изолят пересобирает весь офлайн-пакет из D1: статус + каталог областей +
слоты на 2 дня по всем сетям + группы с улицами + справочник НП + новости. Кеш изолята (5 мин)
помогает только тёплым вызовам; 8 вызовов за 25 минут при нескольких клиентах = постоянные
холодные пересборки. Оценочно **70–80 % суточных rows_read — это `/sync`**.

## Рекомендации (по убыванию эффекта; НЕ применялись)

1. **Перевести `/sync` целиком на R2-снапшот** (как уже сделано с новостями): крон раз в тик
   собирает пакет в `sync/<region>.json` в R2, `/sync` читает один объект (бесплатно), D1
   остаётся только в кроне. Снимает ~70–80 % жгута. Средняя работа.
2. **Справочник НП/улиц из /sync → статический R2-пак** (он уже есть для подсказок адреса).
   Частичная мера, если (1) делать поэтапно.
3. Клиентский опрос `/sync` реже 5 минут / только на Wi-Fi — под вопросом, UX-трейдофф.

Новость снапшотом уже закрыта: с 00:00 UTC `news/latest.json` обновляется кроном, `/news`,
`/news/sources` и новости `/sync` D1 не читают.
