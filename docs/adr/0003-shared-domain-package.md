# ADR-0003: `packages/domain` — единственный источник доменных правил

- **Статус:** Принято (2026-10-27)
- **Дата:** 2026-10-27

## Контекст

Правила предметной области размазаны по четырём кодовым базам:

| Правило | Где реализовано |
|---|---|
| Киевские сутки, DST, минуты суток | `packages/core/src/lib/scheduleWindow.ts`, `cf-worker/src/kyiv-time.ts`, `apps/api` |
| Интервалы 30-минуток, склейка | `cf-worker/src/schedule-utils.ts`, `apps/api/src/services/schedule-normalizer.ts`, Python-парсеры |
| Код группы `2.2` → `2/2` | Worker, Python, api |
| «День опубликован» / `no_data` | Worker, api, Python-тесты |
| Каталог регионов и `feedKeys` | `packages/shared/src/regions-catalog.ts`, `cf-worker/src/regions.ts` |
| Матчинг адреса и очереди | Worker (`resolveAddress`), `packages/core/src/lib/address.ts`, `apps/api` |

Правила уже расходились: инвертированные интервалы Telegram («з 22:00 до 02:00») были
исправлены в Python-движке, но остались в Worker; `/status` отдавал не тот набор полей, что
описан контрактом, — главная падала в белый экран (`cf-worker/src/index.ts:4863`).

Доменные правила не требуют I/O, но живут внутри файлов с SQL, HTTP и React.

## Решение

1. Создаём `packages/domain` — **чистый TypeScript без зависимостей** (кроме стандартной
   библиотеки). Никаких `fetch`, D1, React, zod.
2. Модули домена: `regions`, `schedule`, `publication`, `address`, `reliability`, `news`,
   `outages`, `ingest`, `release`.
3. Экспорт — функции и типы; побочных эффектов нет. Время передаётся параметром (`now`), а не
   читается из `Date.now()` внутри.
4. Worker, `packages/client-core` и `apps/api` (пока жив) **импортируют** домен, а не копируют.
5. Python не может импортировать TS. Поэтому:
   - Python-адаптеры занимаются только транспортом и парсингом в **canonical DTO**;
   - бизнес-правила применяются на границе ingest в TypeScript;
   - корректность DTO проверяется общими golden fixtures (JSON-кейсы) в Python- и TS-тестах.
6. Дублирование правила считается дефектом. Единственное исключение — производительность,
   и оно фиксируется комментарием со ссылкой на этот ADR и тестом на совпадение.

## Последствия

**Положительные**

- Один багфикс доезжает до Worker, PWA и Android одновременно.
- Домен тестируется без D1, сети и React — быстро и детерминированно.
- Появляется возможность property-based тестов (интервалы, границы суток, DST).
- Упрощается онбординг: предметная логика в одном каталоге.

**Отрицательные / риски**

- Нужен рефакторинг с переносом тестов; временно возможны дубли.
- Worker собирается Wrangler'ом отдельно — нужно убедиться, что импорт пакета не тянет лишнее
  (решается отсутствием зависимостей у `domain`).
- Python-часть остаётся «вторым сортом»: правила там не живут, только транспорт.

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| Копировать правила и сверять тестами | уже пробовали: тесты ловят расхождение поздно, после релиза |
| Генерировать Python из TS | хрупкий кодогенератор, сложная отладка |
| Оставить домен в Worker, клиентам отдавать готовый JSON | клиентам нужны те же расчёты офлайн; дублирование неизбежно |
| Вынести домен в отдельный сервис | сетевой вызов на каждый расчёт, противоречит офлайну |

## Критерии приёмки

- [x] `packages/domain` не имеет ни одной runtime-зависимости.
- [x] Каталог регионов существует в одном экземпляре; Worker-копия генерируется или удалена.
- [x] Киевские сутки/DST реализованы один раз и покрыты тестами на переход времени.
- [ ] Python-адаптеры не содержат правил публикации и склейки интервалов.
- [ ] Golden fixtures общие для Python и TS.
