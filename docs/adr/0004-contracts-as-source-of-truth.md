# ADR-0004: Контракты — единственный источник истины; Worker их импортирует

- **Статус:** Принято (2026-10-27)
- **Дата:** 2026-10-27

## Контекст

`packages/shared` содержит zod-схемы и типы ответов API. Worker намеренно **не импортирует**
этот пакет, чтобы «не тащить zod» — контракты скопированы вручную:

- `cf-worker/src/index.ts:408` — копия `computeSyncEtag`;
- `cf-worker/src/index.ts:4268` — копия констант;
- `cf-worker/src/index.ts:4863` — комментарий о расхождении `StatusResponse`, из-за которого
  главная читала `status.grid.level` и падала в белый экран.

Экономия — около 15 КБ в бандле (лимит скрипта Worker — мегабайты). Цена — ручная синхронизация
десятков полей и уже случившийся прод-инцидент.

Дополнительно: `apps/api` имеет собственные представления ответов (Drizzle-схемы + ручные
сериализаторы), которые тоже расходятся с Worker.

## Решение

1. `packages/contracts` — единственный источник схем запросов и ответов (zod).
2. **Worker импортирует контракты напрямую.** zod в Worker разрешён: стоимость бандла
   несопоставима с ценой расхождений.
3. Импорт типов — `import type`, где валидация не нужна; схемы — только на границах:
   ingest, админ-операции, тесты ответов.
4. Тесты Worker проверяют **исходящие ответы** на соответствие схемам (`safeParse`) для всех
   публичных эндпоинтов; ответ, не проходящий схему, — красный тест.
5. OpenAPI и клиентские типы генерируются из схем, а не пишутся руками.
6. Изменение контракта: сначала схема и fixture, затем реализация. Ломающее изменение —
   новое поле/версия эндпоинта, а не тихая замена семантики.
7. `packages/shared` разделяется: контракты → `contracts`, доменные типы/функции → `domain`
   (ADR-0003). Barrel-файл на 956 строк расформировывается.

## Последствия

**Положительные**

- Исчезает класс «контракт формально совпадает, семантика — нет».
- Клиент и сервер компилируются против одного типа; расхождение ловится до деплоя.
- Появляется машинно-проверяемая документация API.

**Отрицательные / риски**

- Бандл Worker немного вырастет; при необходимости — tree-shaking и отказ от тяжёлых схем
  на горячем пути.
- Нужно переписать существующие ручные ответы под схемы (постепенно, по модулям).
- zod-схемы — код, который тоже надо поддерживать; дублирование схем и типов запрещено
  (`z.infer`).

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| JSON Schema + кодогенерация | лишний шаг сборки; zod уже используется в клиентах |
| Оставить ручные копии | уже привело к белому экрану; не масштабируется |
| Валидировать только на клиенте | сервер продолжит отдавать что угодно; ошибки позже и дороже |
| tRPC | жёстко связывает клиентов с сервером, плохо для публичного API и офлайна |

## Критерии приёмки

- [ ] В `cf-worker` нет ручных копий полей/констант из контрактов.
- [ ] Каждый публичный эндпоинт покрыт тестом «ответ соответствует схеме».
- [ ] OpenAPI генерируется из `packages/contracts`.
- [ ] `packages/shared/src/index.ts` больше не является barrel-файлом на 956 строк.
