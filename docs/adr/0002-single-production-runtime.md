# ADR-0002: Один прод-рантайм — Worker; `apps/api` становится oracle

- **Статус:** Принято (2026-10-27)
- **Дата:** 2026-10-27

## Контекст

В репозитории два полноценных бэкенда:

| | `cf-worker` | `apps/api` |
|---|---|---|
| Рантайм | Cloudflare Worker | Node/Fastify |
| БД | D1 (SQLite) | PostgreSQL 16 |
| Прод-трафик | весь | **ноль** |
| Объём | 11 636 строк | 12 837 строк |
| Тесты | ≈102 | ≈427 |
| Таблиц | 10 | 20 |

Поведение расходится: `/street-queues` в Worker всегда `[]`, `/street-queues/schedule` —
«улиця не прив'язана», `/places/:account` — 404. Node-API на тех же путях отдаёт реальные
данные из `street_queues`, `subscriber_places`, `address_queues`. Клиенты вызывают общие
маршруты и получают разную семантику при формально совпадающем контракте.

Следствия: двойная поддержка схем, миграций, парсеров и правил; новый разработчик не понимает,
какой бэкенд «настоящий»; исправление в одном не доезжает до другого; тесты Node-API создают
ложное чувство защищённости прод-пути.

## Решение

1. **Единственный прод-рантайм — Cloudflare Worker** (`cf-worker`).
2. `apps/api` **замораживается**:
   - никаких новых маршрутов, парсеров и миграций;
   - допускаются только исправления безопасности и перенос тестов;
3. `apps/api` сохраняется как **oracle контрактов**: источник golden fixtures и интеграционных
   тестов до тех пор, пока его покрытие не перенесено на Worker (Miniflare + локальная D1).
4. Публичный контракт Worker не содержит заглушек, неотличимых от «нет данных»:
   недоступная в среде функция отвечает явным признаком (`available: false`,
   `source: "unavailable"`) либо удаляется из контракта.
5. PG-only возможности (`places`, `street-queues`, ручные привязки) получают решение:
   перенос в D1 или удаление из публичного API. Решение фиксируется отдельным ADR.

## Последствия

**Положительные**

- Одна схема, один набор миграций, одно поведение в проде.
- Минус ~12,8 тыс. строк поддержки и ~427 тестов, не относящихся к прод-пути.
- Исчезает класс багов «локально работает, в проде заглушка».

**Отрицательные / риски**

- Потеря готовых интеграционных тестов на PostgreSQL — нужно перенести самое ценное.
- Возможна потеря функций, которые есть только в Node-API; решение принимается осознанно,
  а не по умолчанию.
- D1 не поддерживает часть SQL/транзакционных сценариев PG — придётся упрощать.

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| Оставить оба и синхронизировать | требует двух инфраструктур и постоянного сравнения; уже расходится |
| Сделать `apps/api` основным | платный хостинг, больше операционной работы, противоречит free tier |
| Удалить `apps/api` сразу | потеряем oracle и тесты до того, как перенесём покрытие |
| Поднять staging на PG | ещё одна среда для поддержки без пользователей |

## Критерии приёмки

- [x] В `apps/api` нет новых маршрутов/миграций после даты ADR.
- [x] Каждый PG-only маршрут имеет решение: перенесён, скрыт за флагом или удалён.
- [ ] Worker не возвращает пустой массив там, где функция просто не реализована.
- [ ] Интеграционные тесты прод-пути запускаются против Worker (Miniflare/локальная D1).
- [x] `PROJECT_MAP.md` больше не описывает `apps/api` как «резервный прод-путь».
