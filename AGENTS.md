# AGENTS.md — Svitlo (All-Ukraine Power Monitor)

Ты работаешь в монорепо **Svitlo** (`pnpm` workspaces: Fastify 5 + PostgreSQL 16 + Drizzle API, React 19 + Vite 8 + Tailwind v4 PWA, Docker Compose). Масштаб: **вся Украина** (24 области + Киев), закладки групп/адресов, поиск групп по сёлам (`settlements`) и улицам (`street_queues`), каноническое ядро `outage_events`, мульти-парсинг (ОСР, зеркала ГПВ, Telegram, RSS).

## Базовые правила и Экономный режим
1. **Сначала скил:** перед задачей прочитай `skills/agent-discipline/SKILL.md` и профильный скил из таблицы Router. Не открывай лишние файлы.
2. **Честность:** не выдумывай пути, API, версии и графики (`SCHEDULE_DEMO` запрещён). Пустой ответ = честный EmptyState.
3. **Язык:** отвечай на языке пользователя (RU/UA), код — на английском, UI-локализация — только украинская (`uk.json`).
4. **Крупные правки:** заменяй функции и создавай файлы целиком. Если задача >100 правок — остановись на логической границе, закоммить и запиши остаток в `HANDOFF.md`.
5. **Краткость:** вывод команд режь (`| tail -15`). Полный набор тестов гоняй только по просьбе человека; всегда проверяй типы (`tsc --noEmit`).

## Оформление коммитов и версия

Правила обязательны для человека **и** для агентов — история коммитов публичная, её читают как
документацию проекта.

### Коммит

- **Формат:** Conventional Commits — `type(scope): Тема`. Префиксы и scope на английском
  (`feat`, `fix`, `chore`, `docs`, `refactor`, `test`; scope: `api`, `web`, `android`, `tools`).
- **Язык темы и описания — русский.** Смешивать русский и украинский нельзя: история должна
  читаться единообразно.
- **Тема:** до 72 символов, с заглавной буквы, без точки в конце, на��исание глаголом
  («добавить», «вернуть данные», «исправить»), а не «добавлено/исправлено».
- **Описание:** обязательно, если изменение неочевидно. Пиши **почему**, а не что именно
  сделано в diff: какую ошибку это устраняло, почему так, а не иначе. Перенос строк — 72–100
  символов. Для перечислений — маркированный список.
- **Один коммит — одна мысль.** Служебные изменения (обновление `changelog.json`) вливаются
  в содержательный коммит, отдельным «chore: обновить чейджлог» не засоряют историю.
- Коммит описывает результат для пользователя, а не список изменённых файлов.

### «Що нового» и Release-Note

`changelog.json` — не дамп `git log`, а список изменений для человека. Сырые тела коммитов
туда не попадают: в них обоснования для разработчика, имена таблиц, лимиты D1 и прочий
технический мусор.

- Каждый пользовательский `feat`/`fix`/`security` получает в теле коммита trailer:
  `Release-Note: <одна строка по-украински>`. Это текст для UI, поэтому он украинский,
  хотя тема и описание коммита — русские.
- В `Release-Note` пиши пользу для человека, а не реализацию: «Оновлення графіків більше не
  зупиняється через добовий ліміт» вместо «D1 rows_written исчерпан». Без хешей, дат, имён
  файлов, таблиц и эндпоинтов.
- Внутренние правки (`chore`, `docs`, `test`, `ci`, рефакторинг без видимого эффекта) trailer
  не получают и в «Що нового» не попадают.
- Для истории до появления trailer'а тексты лежат в `tools/changelog-notes.json`; один коммит
  может дать несколько пунктов. Файл курируется вручную, внутренние коммиты в него не вносят.
- В интерфейсе версия и дата релиза показываются один раз в шапке, пункты группируются по
  смыслу («Нові можливості», «Виправлення»). Хеши и даты у отдельных пунктов запрещены.

### Tailwind: канонические классы

Если значение выражается шкалой Tailwind v4, arbitrary value — ошибка:

- `min-w-[27rem]` → `min-w-108`, `min-h-[76px]` → `min-h-19`, `max-w-[120px]` → `max-w-30`;
- `rounded-[2px]` → `rounded-xs`, `rounded-[4px]` → `rounded-sm`;
- `grid-cols-[repeat(48,minmax(0,1fr))]` → `grid-cols-48`, `w-[2px]` → `w-0.5`;
- `active:scale-[0.99]` → `active:scale-99`.

Arbitrary-синтаксис остаётся только для `calc()`, `clamp()`, safe-area, сложных grid-шаблонов
и теней с `currentColor`. Проверяет `skills/frontend-ui-change/scripts/check_tailwind_tokens.py`.

### Версия приложения

Версия `X.Y.Z` видна прямо в интерфейсе (нижний угол главной рядом с меткой сборки), она же
попадает в `versionName` Android. Повышается скриптом:

```bash
./tools/bump-version.sh major   # крупное: новая архитектура, новый экран, смена источника данных
./tools/bump-version.sh minor   # среднее: новая функция в существующем экране, новый эндпоинт
./tools/bump-version.sh patch   # мелкое: исправление ошибки, вёрстка, текст
```

- **X** — крупное: смена архитектуры, новый экран, смена источника данных, несовместимое
  изменение формата данных или API. **Меняется первая цифра.**
- **Y** — среднее: заметная новая функция в рамках существующего экрана, новый эндпоинт.
- **Z** — мелкое: исправление ошибки, вёрстка, тексты, обновление зависимостей.
- Правка считается «мелкой», если её можно откатить, не ломая использование продукта.
- Повышенную версию отражают в описании коммита и в `apps/web/src/data/changelog.json`
  (обновляется сам при сборке).

Метка сборки (`build 20261014-0410`) ставится автоматически и меняется при каждой сборке —
это время сборки, а не смысловая версия.

## Permissions — границы полномочий агента

### Часть 1. Разрешено делать БЕЗ вопросов (действуй автономно)
- Читать/править код, конфиги, доки и скилы в репозитории; создавать ветки и коммиты.
- Запускать typecheck (`tsc`), точечные тесты, линтеры, сборку и управлять локальным Docker (`up -d --build`, `logs`, `exec`).
- Создавать новые SQL-миграции (`00XX_*.sql`), накатывать их локально и писать парсеры/провайдеров для новых областей, сёл и улиц.
- Искать и применять обходные пути для получения данных (зеркала, Telegram-каналы, RSS, внутренние API, куки/сессии, headless-браузер).

### Часть 2. Требует ЯВНОГО согласия человека (STOP & ASK)
- **Удаление данных и томов:** `DROP TABLE/COLUMN` на проде, `TRUNCATE`, `docker compose down -v`, удаление `pg_data` или бэкапов.
- **История миграций и git:** изменение уже применённых SQL-миграций, `git push --force`, `git reset --hard` несохранённой работы.
- **Прод и секреты:** деплой на внешний прод-сервер, ротация реальных паролей/токенов, показ или коммит ПД (номеров лицевых счетов).
- **Платные внешние вызовы:** подключение/расход баланса платных CAPTCHA-солверов (`CAPTCHA_SOLVER_API_KEY`), платных прокси и внешних API.

## Финальный чек-лист перед словом «Готово»
```bash
# Из корня репозитория обязателен -p: корневого tsconfig.json нет, только tsconfig.base.json,
# поэтому голый `tsc --noEmit` печатает справку и выходит с кодом 1 (ложная «ошибка типов»).
# Отдельный конфиг для тестов: в `apps/api/tsconfig.json` include — только `src/**`, из-за чего
# ошибки в `tests/**` видел лишь редактор, а проверка их пропускала.
./apps/api/node_modules/.bin/tsc -p apps/api/tsconfig.json --noEmit
./apps/api/node_modules/.bin/tsc -p apps/api/tsconfig.tests.json --noEmit
./apps/web/node_modules/.bin/tsc -p apps/web/tsconfig.json --noEmit
(cd cf-worker && ./node_modules/.bin/tsc --noEmit)
python3 skills/secrets-pii-hygiene/scripts/scan_secrets.py .
python3 skills/frontend-ui-change/scripts/check_tailwind_tokens.py .   # если менялись стили/UI
```
