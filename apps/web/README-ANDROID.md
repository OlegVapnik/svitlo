# Сборка Android-приложения (APK)

Приложение — тот же веб-бандл, что отдаёт nginx, упакованный в нативный контейнер
[Capacitor](https://capacitorjs.com). Нужен для установки на телефон как обычного приложения:
иконка в лаунчере, полноэкранный режим, своя тема, работа без адресной строки браузера.

**На хосте ничего ставить не нужно** — ни JDK, ни Android SDK, ни rsvg. Сборка идёт в Docker
(образ `svitlo-android-builder` из `docker/Dockerfile.android`: JDK 21 + Android SDK 36 +
build-tools 36 + Node.js + librsvg).

## Быстрый старт

```bash
# release-APK с боевым HTTPS-API
./tools/build-android-apk.sh

# либо явно (другой домен/порт)
./tools/build-android-apk.sh https://example.com/api/v1

# debug-сборка для локального сервера (http в той же Wi-Fi сети)
./tools/build-android-apk.sh --debug http://192.168.1.100:3000/api/v1
```

Готовый файл:

```
apps/web/android-apk/svitlo-<версия>.apk   # release, подписанный
apps/web/android-apk/app-debug.apk         # только для --debug
```

## Установка на телефон

1. Скопируйте APK на телефон (Telegram, «Файлы», USB) и откройте его.
2. Разрешите установку из выбранного приложения — это системное разрешение Android.
3. Приложение появится в лаунчере как **«Світло»**.

По USB:

```bash
adb install -r apps/web/android-apk/svitlo-<версия>.apk
```

> **Если раньше стояла debug-сборка**, Android не даст поставить release-версию поверх неё:
> подписи разные. Один раз удалите старое приложение:
>
> ```bash
> adb uninstall ua.com.svitlo.app
> ```
>
> Дальше все release-сборки используют один и тот же ключ и ставятся обновлением.

## Про предупреждение Play Protect

Приложение нельзя заставить Android/Play Protect «молча установить APK»: это системная защита,
и она не управляется из манифеста приложения. Что можно и что сделано:

- собирается **release**, а не debug. Debug-подпись («Android Debug») часто показывается как
  «приложение для разработки»;
- release-сборка подписана постоянным ключом, поэтому обновления ставятся поверх и не требуют
  каждый раз удалять приложение;
- если Play Protect показывает «неизвестное приложение» при первом запуске APK, нажмите
  «Всё равно установить». Отключить проверку можно только вручную:
  **Google Play → профиль → Play Protect → шестерёнка → отключить «Сканировать приложения»**.
  Приложение не может сделать это за вас и не должно пытаться обходить защиту.

## Требования к системе

| Параметр | Значение |
|---|---|
| `minSdkVersion` | 26 (Android 8.0) — база adaptive-иконок |
| `targetSdkVersion` | 35 — требуется Google Play для новых приложений |
| Разрешения | `INTERNET`, `POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM` |

## Как это устроено

| Файл | Роль |
|---|---|
| `tools/build-android-apk.sh` | весь пайплайн: чейджлог → веб-бандл → иконки → `cap sync` → gradle |
| `docker/Dockerfile.android` | образ со JDK 21, Android SDK, Node.js и `rsvg-convert` |
| `apps/web/capacitor.config.json` | id приложения, схема, параметры WebView |
| `apps/web/public/icons/icon.svg` | **единственный исходник иконки** |
| `apps/web/scripts/generate-android-icons.mjs` | SVG → иконки всех плотностей, adaptive-слои, splash, maskable |
| `apps/web/android/` | нативный проект (генерируется `npx cap add android`) |

### Иконка: где менять

Меняйте только один файл:

```
apps/web/public/icons/icon.svg
```

В нём две группы, которые генератор вырезает по отдельности:

- `<g id="background">` — фон, кольца, блик;
- `<g id="foreground">` — молния, тени и искры.

Не добавляйте внутри этих групп вложенные `<g>` и не добавляйте SVG-фильтры: librsvg не
подгружает такой SVG как внешнюю картинку, и splash останется без логотипа. Тени делайте
отдельной фигурой, как в исходнике.

После правки просто пересоберите APK:

```bash
./tools/build-android-apk.sh
```

Скрипт сам сделает из одного SVG:

- `mipmap-*/ic_launcher.png` — обычная иконка лаунчера;
- `mipmap-*/ic_launcher_round.png` — круглая иконка;
- `mipmap-*/ic_launcher_background.png` и `ic_launcher_foreground.png` — adaptive-иконка Android 8+;
- `drawable*/splash.png` — заставки для всех плотностей и ориентаций;
- `public/icons/icon-maskable.svg` — maskable-иконка PWA (фон без скруглений, безопасная зона).

### Release-подпись

При первом release-запуске скрипт создаёт:

```
apps/web/android/app/keystore/svitlo-release.p12
apps/web/android/keystore.properties
```

Оба файла в `.gitignore`. **Сделайте их резервную копию.** Потеря ключа означает, что новую
версию нельзя будет установить поверх старой — только удалить приложение и поставить заново.

### Важно про адрес API

В PWA запросы идут на `/api/v1` — тот же origin, что и страница. В нативном приложении
«localhost» означает сам WebView, поэтому относительный адрес **уведёт запросы в никуда**.
Адрес передаётся через `VITE_API_BASE_URL` на этапе сборки и зашивается в бандл.

Следствия:
- **release** по умолчанию ходит на боевой HTTPS-API; если он переехал — передайте адрес
  аргументом;
- **debug** без аргумента подставляет локальный IP машины и разрешает cleartext только в
  debug-конфиге;
- в release `network_security_config.xml` запрещает http глобально. Это осознанно: боевой
  трафик должен идти по HTTPS.

## Частые проблемы

**Белый экран, «нет соединения».** Проверьте, что адрес в APK совпадает с доступным с телефона:
`curl http://<ip>:3000/api/v1/status` с телефона. Пересоберите с правильным адресом.

**«Приложение не установлено» при обновлении.** Скорее всего, установлена debug-сборка или
APK собран другим ключом. Удалите приложение один раз (`adb uninstall ua.com.svitlo.app`) и
поставьте release. Дальше ключ не меняется.

**PWA-логика внутри приложения.** Service Worker в WebView-контейнере работает, но при обновлении
приложения кэш может удерживать старый бандл. В этом проекте `selfDestroying: true`
(см. `vite.config.ts`), а в нативной сборке регистрация SW вообще вырезается.

**Сборка падает на лицензиях SDK.** В образе они принимаются автоматически (`sdkmanager --licenses`).
Если пересобираете образ вручную и видите интерактив — не хватило `yes |`.
