# Сборка Android-приложения (APK)

Приложение — тот же веб-бандл, что отдаёт nginx, упакованный в нативный контейнер
[Capacitor](https://capacitorjs.com). Нужен для установки на телефон как обычного приложения:
иконка в лаунчере, полноэкранный режим, своя тема, работа без адресной строки браузера.

**На хосте ничего ставить не нужно** — ни JDK, ни Android SDK. Сборка идёт в Docker
(образ `svitlo-android-builder` из `docker/Dockerfile.android`: JDK 21 + Android SDK 36 +
build-tools 36).

## Быстрый старт

```bash
# адрес API можно не указывать — скрипт возьмёт локальный IP машины
./tools/build-android-apk.sh

# либо явно (удобно для домена или другого порта)
./tools/build-android-apk.sh https://світло.ук/api/v1
```

Готовый файл:

```
apps/web/android/app/build/outputs/apk/debug/app-debug.apk
```

## Установка на телефон

1. Включите **«Установка из неизвестных источников»** для приложения, из которого открываете
   APK (Файлы / Telegram / браузер).
2. Скопируйте `app-debug.apk` на телефон и откройте его, либо по USB:

   ```bash
   adb install -r apps/web/android/app/build/outputs/apk/debug/app-debug.apk
   ```

3. Приложение появится в лаунчере как **«Світло»**.

## Требования к системе

| Параметр | Значение |
|---|---|
| `minSdkVersion` | 26 (Android 8.0) — база adaptive-иконок |
| `targetSdkVersion` | 35 — требуется Google Play для новых приложений |
| Разрешения | только `INTERNET` |

Проверено сборкой: `minSdkVersion=26`, `targetSdkVersion=35`, `application-label='Світло'`.

## Как это устроено

| Файл | Роль |
|---|---|
| `tools/build-android-apk.sh` | весь пайплайн: сборка фронта → иконки → `cap sync` → gradle |
| `docker/Dockerfile.android` | образ со JDK 21 и Android SDK |
| `apps/web/capacitor.config.json` | id приложения, схема, параметры WebView |
| `apps/web/scripts/generate-android-icons.mjs` | иконки всех плотностей из одного SVG |
| `apps/web/android/` | нативный проект (генерируется `npx cap add android`) |

### Важно про адрес API

В PWA запросы идут на `/api/v1` — тот же origin, что и страница. В нативном приложении
«localhost» означает сам WebView, поэтому относительный адрес **уведёт запросы в никуда**.
Адрес передаётся через `VITE_API_BASE_URL` на этапе сборки и зашивается в бандл:

```bash
VITE_API_BASE_URL="http://192.168.1.100:3000/api/v1" ./tools/build-android-apk.sh
```

Следствия:
- **локальная сеть.** Работает, пока телефон в той же Wi-Fi сети, а nginx на порту 3000 доступен
  с телефона (не только с `127.0.0.1`).
- **Android 9+ блокирует http-cleartext**, а при `targetSdk 35` это поведение по умолчанию.
  Поэтому http разрешён **не глобально**, а точечно в
  `android/app/src/main/res/xml/network_security_config.xml`: только для `localhost`, `127.0.0.1`
  и адресов локальной сети (`192.168.*`, `10.*`, `172.16.*`). На любой другой адрес приложение
  ходит только по HTTPS. Это и работает с телефоном, и не ослабляет безопасность для боевого домена.

### Иконки

Генерируются собственным скриптом без `sharp`/canvas (их build-скрипты pnpm не даёт запускать,
а на хосте нет Android-инструментов): один SVG-источник → PNG всех плотностей плюс
adaptive-иконка Android 8+. Источник правды один, поэтому иконка приложения и PWA не расходятся.

## Частые проблемы

**Белый экран, «нет соединения».** Проверьте, что адрес в APK совпадает с тем, что доступен
с телефона: `curl http://<ip>:3000/api/v1/status` с телефона. Пересоберите с правильным адресом.

**PWA-логика внутри приложения.** Service Worker в WebView-контейнере работает, но при обновлении
приложения кэш может удерживать старый бандл. В этом проекте `selfDestroying: true`
(см. `vite.config.ts`) — SW снимает сам себя, поэтому после установки обновлённого APK страница
всегда свежая.

**Сборка падает на лицензиях SDK.** В образе они принимаются автоматически (`sdkmanager --licenses`).
Если пересобираете образ вручную и видите интерактив — не хватило `yes |`.
