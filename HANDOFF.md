## Текущее состояние (2026-10-18, версия 2.22.0 в APK, прод на 2.22.0)

### Что работает в проде
- **Графики по группам.** `/queues?region=kyiv-city` → 60 групп со слотами. Ключевое изменение:
  маршруты воркера (`/regions`, `/queues`, `/schedules`, `/schedules/upcoming`, `/status`)
  больше не зависят от одного зеркала — снимок дополняется слотами из `schedule_slots`
  (`MirrorSnapshot.d1Slots` + `loadOwnSlots`).
- **Адресный каскад** локально полностью: Київ/Хрещатик 12 → `20`, Бровари/Симоненка 25 → `3/2`,
  Батурін/Гетьманська 27 → `4/1`, Блістова/Лісова 34 → `3/2`, Варва/2-й Миру 11 → `1/2`.
  В проде пока `null` — данные не залиты.
- **OTA целостна:** `/version` и файл на Pages отдают одинаковый SHA-256.

### Что сломано и ждёт 03:00 (00:00 UTC)
1. **Прод-D1 не обновлён адресами.** Старый Чернигов со слипшимися колонками
   (`settlement_name = "null"`), свежие файлы не залиты.
2. **1 фантом покрытия:** `ivano-frankivska-oblast` — `covered: true` при `lastDate: null`,
   потому что старые строки `schedule_coverage` лежат в проде.
3. **Всё одной командой:** `./tools/release-after-midnight.sh` (подготовлен, синтаксис проверен).

### Лимиты Cloudflare D1 — главная операционная боль
- Free Tier: 5 млн `rows_read` и 100 тыс. `rows_written` в сутки, сброс в 00:00 UTC.
- **Полный `wrangler d1 export` съедает весь суточный лимит** (база 114 МБ, 308 тыс. строк).
  Бэкапить только селективно: `--table schedule_slots --table schedule_coverage
  --table snapshot_meta --table address_queues`. Это вписано в скрипт выкладки.
- `DELETE FROM` тарифицируется построчно: таблицу на сотни тысяч строк сносить через DDL
  (`DROP TABLE` + `CREATE TABLE`), иначе лимит записи выбьется и следующие сутки ничего
  не зальётся.
- Воркер на `D1_ERROR` молча уходит в фолбэк и отвечает HTTP 200 — квота выглядит рабочей.
  Задача: отдавать в `/api/v1/status` флаг `d1QuotaExceeded`.

### Главный инвариант данных
**Зелёный при отсутствии данных запрещён.** Оператор, не опубликовавший график, пишет
`class="no_data"` и «Немає даних» — это НЕ «світло є за графіком».

Правило `is_day_published(block, slots)` в `tools/scrapling_schedules_sync.py`:
побеждает заполненная ячейка `class="hour_status <класс>"` или интервалы; отсутствие
публикации фиксируется, только когда ячеек нет вовсе **и** есть заглушка «Немає даних».
Проверяется тестами `tests/test_scrapling_schedules.py` (8 тестов, фикстуры — живые снимки
Днепра и Сумы плюс честно помеченная синтетика для «все зелёные»).

## 2026-10-18 — КРИТИЧНО: ложное «світло є» у 11 областей найдено и исправлено

### Что было не так
Проверка «11 областей без отключений — это правда?» (обоснованное сомнение владельца) дала
**нет**. На сырых страницах Energy-UA у тернопil, lviv, rivne, zakarpat, zap, khmelnytskyi:
```
class="no_data" ×2, текст «Немає даних» ×2, непустых hour_status: 0
```
То есть оператор **не опубликовал график вообще**, а наш парсер отдавал `covered = true`.

Причина в логике: `covered` считался по наличию блока `scale_hours` в HTML. Но этот блок
(48 ячеек) рендерится **всегда**, даже когда данных нет — поверх него оператор ставит
«Немає даних». Пустой разбор и «свет есть» выглядели одинаково.

### Исправлено
- `tools/scrapling_schedules_sync.py`: день считается опубликованным, только если
  **нет** маркера `no_data`/`Немає даних` **и** есть хотя бы одна заполненная ячейка
  (`class="hour_status <класс>"`) либо интервалы.
- Обнаружено второе следствие: скрипт пишет строки покрытия только для покрытых дней,
  поэтому старые (ложные) строки никогда не удалялись. Перед синком покрытие нужно чистить:
  `DELETE FROM schedule_coverage WHERE source='energy-ua'`.
- После правки в локальной D1: **6 областей с честным покрытием** (chernihivska, kharkivska,
  kyiv-city, kyivska, poltavska, sumska) — ровно те, где есть реальные часы. Остальные области
  честно показывают «немає даних», а не ложную гарантию света.

### Осталось по этой теме
- **`/regions` в воркере всё ещё показывает `covered: true` для 17 областей.** База честная
  (6), значит `covered` приходит из `mirrorFacts.todayCovered`, а тот берёт покрытие из
  зеркала `dtek-api.svitlo-proxy.workers.dev` — там та же ошибка, что была у нас. Либо чинить
  зеркало, либо перестать доверять его покрытию.
- **Правка `lastDate` не сделана** — сознательно отложена: сначала выяснилось, что под
  `lastDate: null` стоит не косметика, а ложное покрытие. Сначала чистка покрытия, потом дата.

### Проверенные вручную источники (обычный curl)
- Тернопіль, Львів, Рівне, Закарпаття, Запоріжжя, Хмельницький — все публикуют
  «Немає даних». Прежнее «світло є» по ним было неправдой.
- `api.loe.lviv.ua/api/menus?type=photo-grafic` — открыт, но графики картинками (`GPV.png`),

### 2. Убраны два холостых чтения пустой `directory_houses`
- `cf-worker/src/index.ts`: удалён запасной SELECT точного дома и запасной SELECT чипов домов
  (раньше строки 3099 и 4220). Таблица намеренно пуста — все дома живут в

- Проверено на локальном стенде: `20`, `3/2`, `4/1`, `1/2` — без изменений; чипы домов по
  Батурину отдают **143** дома из `houses_json`. `tsc` — 0 ошибок. Worker задеплоен: `79fbc7fa`.

### 3. Слежение за свежестью PDF Чернігівоблэнерго — `--check-remote`
- `tools/import-address-hierarchy.py --check-remote --insecure-tls` делает HEAD к PDF оператора
  и сравнивает `Last-Modified`/`Content-Length` с локальным снимком. Коды выхода: 2 — документ
  изменился, пора пересобирать; 0 — свежий; 1 — сравнить не с чем.
- Ничего не скачивает и не пишет, спокоен к любой ошибке сети.
- **Факт сразу после запуска: `Last-Modified: Wed, 07 Jan 2026 14:39:57 GMT`, 6 655 236 байт.**
  То есть документ обновлялся уже после его даты 25.12.2025 — наши очереди взяты из выпуска
  января 2026, им около 9 месяцев.
- Снимок пока без метаданных, поэтому скрипт честно пишет «не означает, что актуален» и
  просит пересобрать один раз с `--json`. Умолчать и написать «актуален» было бы враньём.

### 4. Не сделано: флаг `d1QuotaExceeded` в `/status`
Идея верная, но требует аккуратной обвязки всех `catch` вокруг D1 в воркере, а бюджет сессии
исчерпан. Записано как задача: при `catch` на D1_ERROR сохранять метку времени в модульной
переменной изолята и отдавать её в `/api/v1/status`, чтобы исчерпание квоты было видно без
терминала. Сейчас воркер на D1_ERROR молча уходит в фолбэк и отвечает HTTP 200 — это плохо
и должно быть исправлено.

## 2026-10-18 / 23:40 UTC — «outages.undefined» исправлен

- **Причина:** `/api/v1/outages` вообще не отдавал поле `status` — у всех 300 записей ГПВ оно
  было `null`. Фронтенд собирал ключ как ``t(`outages.${outage.status}`)`` и получал в карточке
  текст `outages.undefined`.
- **Исправлено в воркере:** добавлена функция `outageStatus(startsAt, endsAt)`, которая выводит
  статус из времени — `active` / `scheduled` / `finished`. Поле `status` появилось в ответе.
- **Страховка на фронтенде:** `OutageCard` строит ключ только из белого списка
  `OUTAGE_STATUS_KEYS`, всё остальное получает подпись `outages.scheduled`. Запись без статуса
  больше не может показать ни сырой ключ, ни `undefined`.
- Проверено на живом локальном ответе: `{'scheduled': 300}` — было `{'None': 300}`.
- **Не сделано:** перекрытие «У закладки / Сьогодні / Завтра» в блоке «Стан енергосистеми»
  и редизайн «Точкові відключення (ремонт)». Для первого нужен скриншот — без рендера
  страницы на глаз не проверить, какой именно слой перекрывает какой. Для второго жду решения
  владельца, какой именно вид нужен.
